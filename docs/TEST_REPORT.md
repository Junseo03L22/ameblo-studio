## 실행을 시도했지만 환경에서 막힌 검증

전체 pytest를 실행했을 때 18개 통과, 브라우저 테스트 7개가 setup에서 실패했습니다. 이후 브라우저가 필요 없는 추가 검증을 더하여 위 29개가 통과했습니다.

Chromium을 다운로드했지만 macOS 작업 샌드박스에서 프로세스 시작이 차단됐습니다:

```
bootstrap_check_in ... MachPortRendezvousServer ... Permission denied (1100)
TargetClosedError: BrowserType.launch
```

이 오류를 테스트 통과나 단순 skip으로 처리하지 않았습니다. 실행 가능한 로컬 HTML fixture 테스트 7개를 `browser` 마커로 보존했습니다. 일반 개발 환경/Windows CI에서 `python -m pytest -q`로 실행하세요.

해당 테스트는 임시저장 전용 클릭, 초안 라디오 확인, 공개 범위 확인, 선택자 중복 차단, 리치 본문 입력/불일치 감지, iframe fallback을 검증합니다. 실제 Ameblo에 게시하지 않습니다.

- 실제 키를 사용하는 OpenAI/Gemini 호출과 계정별 모델 이용 가능 여부
- 로그인/2FA 후 전용 프로필 세션 복원
- 실제 Ameblo 에디터의 상태 업데이트, 이미지 업로드, 최종 저장 버튼 및 완료 메시지
- 임시저장 후 다시 연 글의 이미지·본문·비공개 상태
- 실제 전체 공개 발행
- Windows PyInstaller 빌드 및 새 PC 실행
- macOS 앱 번들 생성, 배포 서명/공증

이 배포물은 **MVP 소스와 빌드 구성**입니다. 실제 사이트까지 검증된 완제품 exe가 아닙니다.

## 실제 계정 인수 테스트 체크리스트

1. 테스트 계정과 공개 발행 OFF 상태에서 로그인·세션 재사용 확인.
2. 이미지 없는 테스트 글을 브라우저 검수까지 입력. 제목과 원문 가격 일치 확인.
3. 검수 후 임시저장, 글 목록에서 비공개 확인, 다시 열어서 내용 확인.
4. 이미지 1장 → 여러 장 → 서로 다른 위치 → 같은 위치 순서 확인.
5. 에디터에 기존 내용이 있을 때 덮어쓰지 않는지 확인.
6. 로그인 만료, 업로드 실패, 완료 메시지 미확인 시 진단 파일/중복 경고 확인.
7. 공개 설정을 켜지 않은 상태에서 어떠한 공개 동작도 발생하지 않는지 확인.
8. 별도 테스트 글에서만 명시적으로 전체 공개 발행 검증.
9. Windows에서 빌드 후 Python이 없는 새 사용자 환경에서 로그인/미리보기/저장 검증.
